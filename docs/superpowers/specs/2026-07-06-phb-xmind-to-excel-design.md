# PHB XMind 转 Excel 测试用例设计规格

## 背景与目标

本项目需要将 `狮子项目/PHB-v1.0.xmind` 中的测试点转换为符合 `狮子项目/Qos_DiffServ_PHB_testcases.xlsx` 风格的 Excel 测试用例文件。

- **输入**：`狮子项目/PHB-v1.0.xmind`（XMind 新版格式，含 `content.json`）
- **模板**：`狮子项目/Qos_DiffServ_PHB_testcases.xlsx`（182 行、18 列）
- **输出**：`狮子项目/PHB_testcases_from_xmind.xlsx`

## 输入分析

### XMind 文件

- 格式：新版 XMind（`content.json`）
- 根标题：`狮子项目脑图-PHB-欢迎页`
- 叶子节点数：323 个
- 叶子节点深度分布：3~10 层

### Excel 模板列结构

模板共 18 列：

1. 测试产品
2. 测试模块
3. 优先级
4. 测试类型
5. 脚本名称
6. 用例编号
7. 用例标题
8. 前置条件
9. 测试步骤
10. 预期结果
11. 测试点/测试点
12. 测试场景
13. 所属测试方案
14. 作者
15. 状态
16. 适用平台实现自动化
17. 测试人/测试日期
18. 测试备注

## 设计方案

### 整体流程

1. 读取 `content.json`，递归展开为完整路径树。
2. 识别叶子节点，每个叶子节点对应一条候选用例。
3. 过滤纯说明性节点（如「功能需求说明」等无测试语义的概述节点）。
4. 按模板列结构填充字段。
5. 对无法从 XMind 推断的字段标注「待补充」并设置醒目背景色。
6. 写入新 Excel 文件。

### 字段映射规则

| 列 | 取值规则 |
|---|---|
| 测试产品 | 沿用模板默认值：`57.6T SU Switch(#58)` |
| 测试模块 | 沿用模板默认值：`/Qos/DiffServ/PHB` |
| 优先级 | 默认 `1`；如涉及异常/边界场景可设为 `3` |
| 测试类型 | 沿用模板默认值：`系统测试-功能` |
| 脚本名称 | 留空 |
| 用例编号 | 沿用模板前缀风格顺序编号，如 `sz-phb-eth-f-001`、`sz-phb-sue-f-001` 等；无法归类的统一使用 `sz-phb-auto-xxx` |
| 用例标题 | 叶子节点标题 |
| 前置条件 | 若能从父路径/关键词推断，按模板风格生成；否则填「待补充」 |
| 测试步骤 | 同上 |
| 预期结果 | 同上 |
| 测试点/测试点 | 拼接父路径为 `PHB>...>TCx` 形式 |
| 测试场景 | 基于叶子标题和父路径生成简短描述；无法推断则「待补充」 |
| 所属测试方案 | 沿用模板默认值：`/业务测试/系统测试(#15900)` |
| 作者 | 沿用模板占位：`欢迎页` |
| 状态 | 沿用模板占位：`欢迎页` |
| 适用平台实现自动化 | 沿用模板默认值：`芯片名称、拥塞管理等(#13073)` |
| 测试人/测试日期 | 留空 |
| 测试备注 | 若节点关键词包含环境信息则填充，否则留空 |

### 用例编号前缀规则

沿用模板中已有的分类前缀：

- 标题含 `eth` / `以太` / `IPv4` / `IPv6` 等 → `sz-phb-eth-f-xxx`
- 标题含 `sue` / `SUE` → `sz-phb-sue-f-xxx`
- 标题含 `hsloe` / `holse` → `sz-phb-hsloe-f-xxx`
- 其他无法归类 → `sz-phb-auto-xxx`

各类前缀独立递增编号。

### 待补充字段处理

- 单元格内容填写：`待补充`。
- 背景色：使用醒目的黄色（如 `FFFF00`），便于人工 review 时快速定位。
- 字体颜色保持默认黑色，确保可读性。

### 过滤规则

以下节点不生成用例：

- 标题为空或仅含空白。
- 标题为纯目录/说明性质，例如「功能需求说明」「接口工作模式优先级映射」等无具体验证点的节点。
- 标题以数字序号开头但内容仅为特性声明、无验证动作（如「支持自定义 802.1p 到内部优先级映射」单独作为特性说明时）。

## 边界与异常处理

- 若 XMind 中无有效叶子节点，则输出仅含标题行的空 Excel。
- 若模板文件不存在或损坏，脚本应报错并退出。
- 用例编号超过 999 时，统一使用 4 位数字补齐。

## 验证标准

1. 生成的 Excel 文件可在 `狮子项目/` 下正常打开。
2. 标题行与模板一致，共 18 列。
3. 所有行均包含非空的用例编号和用例标题。
4. 含「待补充」的单元格背景色为醒目的黄色。
5. 用例总数不少于有效叶子节点数（过滤后）。
