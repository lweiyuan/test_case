# Veroce 错误处理测试用例生成设计

## 背景与目标

项目已有一份《多 PF 测试-测试用例.xlsx》，其字段格式、列顺序和填写规范已被 NIC100 测试框架认可。另有一份《veroce 错误处理.xlsx》，记录了 Veroce 芯片在 RDMA 接收路径上各类错误（如 `load_qpc_rcms_err`、`opcode_err`、`dma_err` 等）的触发方式、处理行为与可观测现象。

目标：参考《多 PF 测试-测试用例.xlsx》的格式规范，将《veroce 错误处理.xlsx》中的错误条目转化为一份可直接被测试框架读取/执行的测试用例 Excel 文件。

## 输入输出

- **输入**：`veroce错误处理.xlsx`
  - 使用 sheet：`错误处理`
  - 共 18 条有效错误记录（第 2~19 行；第 20~21 行为空行），14 列
- **输出**：`veroce错误处理-测试用例.xlsx`
  - 使用 sheet：`测试用例`
  - 列头与《多 PF 测试-测试用例.xlsx》完全一致，共 26 列

## 实现方式

采用一次性 Python 脚本完成读取与生成，保持最小侵入：

- **脚本路径**：`ps3/test/esat/nic100/framework/biz/excel/veroce_err_case_generate.py`
- **依赖**：项目已有的 `openpyxl`（已安装于 `.venv`）
- **运行命令**：
  ```bash
  .venv/Scripts/python.exe ps3/test/esat/nic100/framework/biz/excel/veroce_err_case_generate.py
  ```
- **输出位置**：项目根目录 `veroce错误处理-测试用例.xlsx`

脚本不修改任何源 `.xlsx` 文件，仅读取源数据并按模板写入新文件，符合项目“不要直接修改 `.xlsx` 源文件，应通过代码生成或处理”的规范。

## 异常与边界处理

1. 源表单元格为 `None` 时，输出空字符串，避免写入 `None`。
2. 若源表行中“测试场景/测试步骤”或“错误名称”为空，则跳过该行（避免生成无意义用例）。
3. 非法 Excel 字符（控制字符）在写入前过滤，防止 `openpyxl` 报错。
4. 列宽沿用框架常量 `constants.EXCEL_COL_WIDTH`，与现有报告 Excel 风格一致。

## 验证方式

1. 运行脚本后，检查根目录是否生成 `veroce错误处理-测试用例.xlsx`。
2. 用 openpyxl 读取输出文件，确认：
   - sheet 名为 `测试用例`
   - 第 1 行列头与《多 PF 测试-测试用例.xlsx》完全一致
   - 数据行数为 18 行
   - 关键列（测试编号、用例标题、测试步骤、预期结果）无空值
