# iperf 工具使用技巧（基于 10.17.44.73 环境）

## 1. 环境信息

| 项目 | 内容 |
|------|------|
| 主机 | `fpga44-73` |
| OS | Linux 5.14.0-162.6.1.el9_1.x86_64（RHEL 9.1） |
| iperf 版本 | `iperf 2.0.8 (6 Mar 2015)` |
| iperf3 版本 | `iperf 3.9 (cJSON 1.7.13)` |
| 安装包 | `iperf-2.0.8-2.fc23.x86_64`、`iperf3-3.9-9.el9.x86_64` |

## 2. iperf2 vs iperf3 关键差异

| 特性 | iperf 2.0.8 | iperf3 3.9 |
|------|-------------|------------|
| 多播支持 | **支持**，服务端可用 `-B <multicast_addr>` 加入多播组 | **不支持**服务端绑定多播地址 |
| 双向测试 | `-d` / `-r` | `--bidir` / `-R` |
| 输出格式 | 文本 / CSV (`-y C`) | 文本 / JSON (`-J`) |
| 默认端口 | 5001 | 5201 |
| UDP 默认包长 | 8 KB | dynamic / 1460 |
| 并发流 | `-P` | `-P` |
| 绑定源地址 | `-B` | `-B` |

> **结论**：IB 多播测试中的 `iperf -s -u -B 224.0.0.2` 属于 **iperf2 语法**，在 10.17.44.73 上必须使用 `iperf`（2.0.8），不能用 `iperf3`。

## 3. IB 多播测试常用命令

### 3.1 服务端（加入多播组）

```bash
# IPv4 多播服务端，绑定到多播地址 224.0.0.2
iperf -s -u -B 224.0.0.2 -i 1

# 参数说明
# -s : 服务端模式
# -u : UDP 协议
# -B : 绑定到多播地址，服务端通过该地址加入多播组
# -i 1 : 每 1 秒输出一次带宽统计
```

### 3.2 客户端（向多播组发送）

```bash
# IPv4 多播客户端
iperf -c 224.0.0.2 -u -l 128 -i 1 -t 1000 -B 192.168.100.1

# 参数说明
# -c 224.0.0.2 : 目标为多播地址
# -u : UDP 协议
# -l 128 : 数据包长度 128 字节
# -i 1 : 每秒报告
# -t 1000 : 测试 1000 秒
# -B 192.168.100.1 : 指定客户端源 IP
```

### 3.3 2v2 多对多多播场景（MC-16）

服务器 A：
```bash
ip route add 224.0.0.2 dev ib0
iperf -s -u -B 224.0.0.20 -i 1
```

服务器 B：
```bash
ip route add 224.0.0.2 dev ib0
iperf -s -u -B 224.0.0.20 -i 1
```

服务器 A 作为客户端：
```bash
iperf -c 224.0.0.20 -u -T 5 -l 128 -i 1 -t 1000 -B 192.168.100.1
```

服务器 B 作为客户端：
```bash
iperf -c 224.0.0.20 -u -T 5 -l 128 -i 1 -t 1000 -B 192.168.100.2
```

## 4. 关键参数速查

### iperf2 常用参数

| 参数 | 含义 | 多播场景 |
|------|------|----------|
| `-s` | 服务端 | 必须 |
| `-c <host>` | 客户端，连接目标 | 目标写多播地址 |
| `-u` | UDP | 多播必须用 UDP |
| `-B <host>` | 绑定地址 | 服务端绑定多播地址以加入多播组；客户端绑定源 IP |
| `-T <ttl>` | TTL，多播默认 1 | 跨网段需增大 |
| `-t <sec>` | 测试时长 | 长稳测试常用 1000/3600/7*24h |
| `-i <sec>` | 报告间隔 | 常用 1 |
| `-l <len>` | 包长 | 常用 128、1024、1460 |
| `-P <n>` | 并行流 | 压力测试用 |

### iperf3 常用参数

| 参数 | 含义 |
|------|------|
| `-s` | 服务端 |
| `-c <host>` | 客户端 |
| `-u` | UDP |
| `-B <host>` | 绑定本地地址（**不能绑定多播地址做服务端**） |
| `-R` | 反向模式（server→client） |
| `--bidir` | 双向同时测 |
| `-J` | JSON 输出 |
| `--get-server-output` | 获取服务端结果 |

## 5. 注意事项

1. **多播必须用 iperf2**：10.17.44.73 上 `iperf3 -s -B 224.0.0.2` 无法让服务端加入多播组。
2. **路由配置**：多播客户端和服务端都需要 `ip route add 224.0.0.2 dev ib0`，否则数据包不会从 ib0 发出。
3. **防火墙**：确保 UDP 目标端口（默认 5001）未被防火墙拦截。
4. **TTL**：同子网内多播 TTL 默认 1 即可；跨子网需要 `-T` 增大。
5. **版本一致性**：iperf2 与 iperf3 不兼容，测试两端需使用相同版本。
6. **iperf2 `-B` 行为**：在服务端 `-B` 用于监听多播地址；在客户端 `-B` 用于指定源地址。

| 用例 | 原命令/描述 | 建议 |

## 7. 快速验证命令

在 10.17.44.73 上可直接执行：

```bash
# 确认版本
iperf -v
iperf3 -v

# 确认多播绑定能力（iperf2 可用）
iperf -s -u -B 224.0.0.2 -i 1
```
